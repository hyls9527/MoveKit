# 质量保障记录 03 — 第三轮迭代优化（性能）

日期：2026-08-02

## 1. 迭代目标

优化大目录迁移下的响应速度与资源利用率：减少重复目录遍历、控制 Wails IPC 事件频率，保证高文件数场景的稳定性。

## 2. 迭代范围

- `app.go`：进度事件节流；
- `internal/migrate/migrate.go`：跳过必然无冲突的全量冲突扫描；
- `app_test.go`：节流逻辑单元测试。

## 3. 验收标准

- 迁移进度事件不超过每 150ms 一次（阶段切换事件除外）；
- 目标目录不存在时不再遍历源目录做冲突检测（少一次全量 WalkDir）；
- 全部现有测试不回归。

## 4. 实施内容

### 4.1 进度事件节流（`app.go`）

原实现每个文件复制完成都 `runtime.EventsEmit` 一次。数万小文件场景会向 WebView 发送数万条 IPC 消息，造成前端卡顿。

修复：新增 `progressThrottle` 纯逻辑类型（150ms 间隔；`starting`/`complete` 阶段始终放行），在 `StartMigration` 的进度回调中统一节流。

### 4.2 跳过无意义的冲突扫描（`internal/migrate/migrate.go`）

迁移前 `PreCheck` 已保证目标目录不存在（存在即返回 `TARGET_EXISTS`），随后 `DetectConflicts` 仍会完整遍历源目录——必然返回 0 冲突，属于浪费。

修复：仅当目标路径存在时才执行 `DetectConflicts`；目标缺失时直接跳过。复制阶段的按文件冲突防护（TOCTOU）保持不变。

## 5. 性能收益分析

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 大目录迁移（10 万文件） | 1 次冲突遍历 + 1 次计数遍历 + 1 次复制遍历 + 10 万次进度事件 | 1 次计数遍历 + 1 次复制遍历 + ≤ 数百次进度事件 |
| 前端渲染 | 事件风暴，进度条高频重绘 | 150ms 节流，渲染稳定 |

## 6. 验证结果

```
go test ./...  PASS
go vet ./...   PASS
```

新增 `TestProgressThrottle`（间隔内丢弃、阶段切换放行、时间推进后放行）。

## 7. 架构稳定性确认

- 节流为纯展示层优化，不改变后端迁移语义与进度计数；
- 冲突扫描跳过条件与 `PreCheck` 语义严格一致（目标存在时才可能冲突）；
- 无新增全局状态（节流状态属于单次迁移闭包）。

结论：第三轮迭代目标达成，性能与稳定性提升，架构稳定。
